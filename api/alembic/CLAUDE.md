# CLAUDE.md — api/alembic/

Database migrations (PostgreSQL 16). Run from `api/`.

```bash
uv run alembic revision --autogenerate -m "what_changed"
uv run alembic upgrade head
uv run alembic history
```

- **Never edit or delete a revision that exists in `versions/`** — it may be applied on the
  production server. Fix mistakes with a new revision.
- Always review autogenerated code: check enums, server defaults, indexes and data backfills.
- New NOT NULL columns on existing tables need a `server_default` or a backfill step.
- Migrations only go forward in practice (rollback = restore a backup), but still write a
  sensible `downgrade()`.
- `tests/core/test_migrations.py` and the test DB setup run every revision from scratch: run
  `uv run pytest tests/core/test_migrations.py` after adding one.
- `versions/` is excluded from ruff; keep it readable anyway.
